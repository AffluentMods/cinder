# Screenshot capture protocol

The README shows four screenshots. This is how they are taken so they look
consistent, and so nothing in them can come back to bite the project.

## Hard rules

1. **Never capture real case material.** Every shot uses synthetic evidence you
   generated yourself, or a public test corpus with a licence that permits
   redistribution (NIST CFReDS, Digital Corpora). If you cannot say where a byte
   in the frame came from, do not publish the frame.
2. **No personal data in the chrome either** — check the window title, the
   recents list, the path bar, and the case name. The recents list is the one
   people forget; it persists across runs and will happily show
   `C:\Users\<your-name>\Cases\real-client-matter`.
3. **No API keys, tokens, or provider names** in the AI copilot panel.

## Setup

- **Window size:** 1600 × 1000 logical pixels (`--size 1600x1000`). Wide enough that no panel
  collapses, small enough that text stays readable when GitHub scales the image
  into a two-column table.
- **Theme:** dark. It is the default and it is what the design system is tuned
  for.
- **Scaling:** capture on a display scaled to 150 % or 200 % and downscale to 1600px
  wide, so the text edges stay crisp on high-density displays.
- **Format:** PNG. Strip metadata before committing — `exiftool -all= *.png`.
  A screenshot carries the capturing machine's details otherwise.

## The six shots

| File | Tool | What must be visible |
|---|---|---|
| `home.png` | Home | An open case, three or four recent cases, recent evidence, the first-time guide. |
| `hex.png` | Hex Viewer | An image open at a non-zero offset, a multi-byte selection with the data inspector decoding it (a FILETIME reads well), and at least one bookmark. |
| `filesystem.png` | Filesystem | A volume listed with record numbers, sizes and timestamps. |
| `imager.png` | Disk imager | A finished run: the source and output paths, and the result with bytes written and both hashes. |
| `report.png` | Reports | A section with text, the Markdown preview, and bookmarks loaded as exhibits. |
| `palette.png` | Command palette | The palette open over the Hex Viewer, with commands and their shortcuts listed. |

An Event Log shot would be a natural seventh, but there is no synthetic `.evtx` to take it
from yet, and a log exported from a real machine carries its computer name and account SIDs,
which rule 1 forbids.

Save them to `assets/screenshots/`; the README shows them in three two-column tables.

## How to produce them

The shots are captures of the real window, taken without clicking through the app by hand.
Cinder's `--shot` switch is a development harness: it opens the window in a given state from
the command line, uses a temporary recents file, never reads or writes your settings or
window layout, and exits by itself. With `--hold <seconds>` it keeps the window on screen
long enough for `tools/screenshots/Capture-Window.ps1` to save it. That script captures the
one window (not the screen), so nothing else on your desktop can end up in a frame.

1. **Evidence.** Unpack `tests/fixtures/ntfs-walker-fixture.img.gz` (an 8 MiB NTFS volume
   generated by `tools/ntfs-fixture-gen`; nothing on it came from a real system) into a
   folder named `cinder-demo\evidence`, as `WKS-014-USB.img`.
2. **Paths.** Map that folder's parent to a drive letter (`subst R: <folder>`) so no path in
   a frame contains your user name. Remove the mapping afterwards (`subst R: /D`).
3. **Capture** with a Release build, on a display scaled to 150 % or 200 %. `--seed-case`
   creates the demo case and its bookmarks, and `--imager-demo` images the fixture to an
   E01 (both only write inside a folder named `cinder-demo`); `--examiner` supplies the name shown instead of your account name.

```powershell
$exe  = 'src\Cinder.App\bin\Release\net10.0\Cinder.exe'
$case = 'R:\cinder-demo\cases\WKS-014-USB.cinder'
$img  = 'R:\cinder-demo\evidence\WKS-014-USB.img'

function Shot($name, $wait, $extra) {
    $argv = @('--shot', "R:\shots\render-$name.png", '--size', '1600x1000', '--examiner', 'm.okafor', '--hold', '12') + $extra
    $argv = $argv | ForEach-Object { if ($_ -match '\s') { '"' + $_ + '"' } else { $_ } }
    $p = Start-Process $exe -ArgumentList $argv -PassThru
    Start-Sleep -Seconds $wait
    tools\screenshots\Capture-Window.ps1 -ProcessId $p.Id -Out "R:\shots\$name.png"
    $p.WaitForExit(30000) | Out-Null
}

Shot home 8 @('--tool', 'dashboard', '--fresh-recents',
    '--seed-case', "$case|WKS-014 removable media|m.okafor|$img",
    '--recent-case', 'Kiosk memory capture|j.alvarez|R:\cinder-demo\cases\KSK-002.cinder',
    '--recent-case', 'Mail server export|m.okafor|R:\cinder-demo\cases\MX-031.cinder',
    '--recent-case', 'Finance laptop triage|j.alvarez|R:\cinder-demo\cases\FIN-118.cinder',
    '--recent-evidence', $img, '--case-file', $case, '--delay', '1800')

Shot hex 9 @('--case-file', $case, '--tool', 'hex', '--open', $img,
    '--hex-bookmark', '0x0', '--hex-bookmark', '0xCF000', '--hex-bookmark', '0xD7C00',
    '--caret', '0xD7C50', '--select', '0xD7C50:0xD7C57', '--delay', '3500')

Shot filesystem 10 @('--case-file', $case, '--tool', 'filesystem', '--evidence', $img, '--delay', '4000')

Shot imager 10 @('--case-file', $case, '--tool', 'imager',
    '--imager-demo', "$img|R:\cinder-demo\images\WKS-014-USB.E01", '--delay', '2500')

Shot report 8 @('--case-file', $case, '--tool', 'reports', '--report-demo', '--delay', '2500')

Shot palette 9 @('--case-file', $case, '--tool', 'hex', '--open', $img,
    '--caret', '0xD7C50', '--select', '0xD7C50:0xD7C57', '--palette', '--delay', '3500')
```

4. **Downscale** each capture to 1600 wide (Lanczos) and save as PNG without metadata. Then
   look at every frame at full size before committing: title bar, recents, paths, examiner
   name.

The offsets in the hex shot are for this fixture: `0xD7C50` is the creation time in the
`$STANDARD_INFORMATION` attribute of `big.bin`'s MFT record. If the fixture is regenerated
they will move.

`--shot` on its own (without `--hold`) writes an off-screen render of the same window to the
given file. That is what the review contact sheets are made from, and it works anywhere,
including without a display scale. Use it at `--scale 1` only: at other scales the
off-screen renderer misplaces the content of anything with a drop shadow (the command
palette, the help panel), which the real window does not do.
