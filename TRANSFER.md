# Transferring the Cinder dev environment to another PC

**Everything the project needs is on GitHub** (main + all tags, all
history rewritten to strip AI co-author trailers). This file catalogues
the small handful of things that live **outside** the repo and need
manual attention on the new machine.

Total time to a working dev checkout on a fresh machine: **~20 minutes**
(most of which is `dotnet restore` downloading NuGet packages).

---

## 1. Bootstrap the machine (10 min)

```powershell
# Install dev prerequisites via winget
winget install Microsoft.DotNet.SDK.10
winget install Python.Python.3.13         # sidecar runtime (vol3, pypff)
winget install Python.Python.3.12         # alternate — some libs prefer 3.12
winget install Git.Git
winget install GitHub.GitLFS
winget install JetBrains.Toolbox          # then install Rider through Toolbox

# Optional but recommended
winget install Microsoft.VisualStudioCode
```

Verify:
```powershell
dotnet --version    # expect 10.0.x
python --version    # expect 3.12 or 3.13
git --version
git lfs version
```

---

## 2. Set your git identity (2 min)

Same identity as this box, so commits attribute correctly:

```powershell
git config --global user.name  "affluent"
git config --global user.email "affluentzombie@gmail.com"
git config --global init.defaultBranch main
```

---

## 3. Clone and restore (5 min)

```powershell
mkdir C:\Users\<you>\RiderProjects
cd    C:\Users\<you>\RiderProjects
git clone https://github.com/AffluentMods/cinder.git
cd cinder
dotnet restore
```

**First push from the new box** will trigger the Git Credential Manager
browser flow — sign in to GitHub, authorise `AffluentMods/cinder`, and
the credential is cached for every future push. No PAT to hand-copy.

## 4. What lives outside GitHub — decide per-item

The following DOES NOT live in the repo. Decide whether each item is
worth carrying across:

### Machine-bound (safe to leave behind, will regenerate)

| Item | Old-PC path | What it is | New-PC action |
|---|---|---|---|
| Cinder logs | `%LOCALAPPDATA%\Cinder\logs\` | Serilog rolling logs of your dev-time launches | **Leave behind** — regenerated on next launch |
| Cinder settings | `%LOCALAPPDATA%\Cinder\settings.json` | AI-provider config; DPAPI-encrypted API keys | On this box: **not present** (never configured). If you configure AI on old box later, re-enter provider + key on new box — DPAPI-encrypted values are **machine-bound and won't decrypt across boxes**. |
| Python venv | `%LOCALAPPDATA%\Cinder\venv\` | Sidecar libraries (evtx, regipy, vol3, pypff) | **Leave behind** — `PythonBootstrap` rebuilds it on first launch of a sidecar tool |
| Rider `.idea/` | `RiderProjects\cinder\.idea\` | Personal IDE settings, breakpoints, run configs | **Leave behind** — regenerated by Rider on first project open |
| `bin/` `obj/` | throughout repo | Build outputs | **Leave behind** — regenerated by `dotnet build` |

### Cross-machine (worth transferring if you have them)

| Item | Old-PC path | Why transfer | New-PC action |
|---|---|---|---|
| Jimmy Wilson E01 | `Downloads\2020JimmyWilson.E01` | Your end-to-end regression-test image for the EWF reader — recorded SHA1 verified byte-exact against the ingester | Copy the 295 MB file across if you want the fast smoke-test on new box; otherwise re-download from wherever you got it originally |
| Extracted case fixtures | `Downloads\jw-extract\` | The 158 MB extraction from the case study — registry hives, .evtx, emails etc. | **Skip** — they regenerate from the .E01 in ~10 minutes |
| Any local test cases | anywhere | Real case data | Move on encrypted media only; per SECURITY.md never commit case data |

### Optional convenience

| Item | Path | Note |
|---|---|---|
| Windows Terminal profile | `%LOCALAPPDATA%\Packages\Microsoft.WindowsTerminal_*\LocalState\settings.json` | If you customised the profile |
| PowerShell profile | `$PROFILE` (`Documents\PowerShell\Microsoft.PowerShell_profile.ps1`) | If you set aliases |
| SSH known_hosts | `%USERPROFILE%\.ssh\known_hosts` | Not required — regenerates on first ssh |

## 5. Verify the new checkout (3 min)

```powershell
cd C:\Users\<you>\RiderProjects\cinder
dotnet build -c Release              # expect: 0 warnings, 0 errors
dotnet build src\Cinder.App -c Debug # expect: 0 errors
dotnet run   --project src\Cinder.App
# Cinder window should open showing the home dashboard
```

If Release build fails, check `Directory.Packages.props` — the vuln
pins (`SQLitePCLRaw.*` 2.1.12, `Microsoft.Build.Tasks.Git` 10.0.401,
`System.IO.Hashing` 10.0.12, `Tmds.DBus.Protocol` 0.21.3) must all
be present.

## 8. What's on the old PC that you should destroy before repurposing it

If you're wiping this box or handing it to someone else:

- `%LOCALAPPDATA%\Cinder\` — if you ever entered API keys, DPAPI values
  are theoretically decryptable by the same-user-on-same-machine, so
  clear the folder before disposal.
- `%USERPROFILE%\.gitconfig` — has your email but no secrets.
- Windows Credential Manager entries for `git:https://github.com` —
  clear via `cmdkey /delete` or Control Panel → User Accounts →
  Credential Manager.
- Any evidence images in `Downloads\` — treat every DFIR sample as if
  it might contain sensitive strings.
